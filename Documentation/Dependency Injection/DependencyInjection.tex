\section{Dependency Injection System}
\label{sec:dependency_injection}

\subsection{Overview}
The \texttt{MLGWorks.Utils.DependencyInjection} system provides a lightweight and extensible approach to managing dependencies within Unity projects using a Service Locator pattern.

This system supports:
\begin{itemize}
    \item Manual service registration for pure C\# classes and select MonoBehaviours.
    \item Automatic dependency injection using attributes.
    \item Lifecycle initialization via an interface.
    \item Automatic registration of marked MonoBehaviours.
\end{itemize}

\subsection{Registering Services}

\subsubsection*{Pure C\# Services}
Pure C\# services should be registered manually in a dedicated \texttt{ServiceBootstrapper} MonoBehaviour with a very early execution order:

\begin{verbatim}
// Example
ServiceLocator.Register<Logger>(new Logger());
ServiceLocator.Register<GameSettings>(new GameSettings());
\end{verbatim}

\texttt{ServiceBootstrapper} is executed during the \texttt{Awake()} phase and is responsible for setting up non-MonoBehaviour dependencies early in the lifecycle.

\subsubsection*{MonoBehaviour Services}
MonoBehaviours that are services and should be registered automatically must be marked with the \texttt{[DIService]} attribute:

\begin{verbatim}
[DIService]
public class MyService : MonoBehaviour { }
\end{verbatim}

These services will be registered automatically during the \texttt{Awake()} phase of the \texttt{DIInitializer}, which runs after most other scripts.

\subsection{Dependency Injection}

To inject a service into a field, decorate it with the \texttt{[Inject]} attribute:

\begin{verbatim}
public class MyComponent : MonoBehaviour
{
    [Inject] private Logger _logger;

    private void Start()
    {
        _logger.Log("Injected successfully!");
    }
}
\end{verbatim}

All MonoBehaviours in the scene (including inactive ones) are scanned and injected at runtime by the \texttt{DIInitializer}.

\subsection{Lifecycle Initialization}
If a MonoBehaviour needs to perform logic after injection is complete, it should implement the \texttt{IInitializable} interface:

\begin{verbatim}
public class MyComponent : MonoBehaviour, IInitializable
{
    [Inject] private GameSettings _settings;

    public void Initialize()
    {
        Debug.Log("Initialized with settings: " + _settings);
    }
}
\end{verbatim}

\texttt{DIInitializer} will automatically call \texttt{Initialize()} after injecting dependencies.

\subsection{Execution Order}
\begin{itemize}
    \item \textbf{ServiceBootstrapper:} Runs early (\texttt{DefaultExecutionOrder = -1000}). Registers core services.
    \item \textbf{DIInitializer:} Runs late (\texttt{DefaultExecutionOrder = 10000}). Injects dependencies and calls \texttt{Initialize()}.
\end{itemize}

\subsection{Best Practices}
\begin{itemize}
    \item Register all non-MonoBehaviour services manually in \texttt{ServiceBootstrapper}.
    \item Use \texttt{[DIService]} to mark MonoBehaviours that should be registered automatically.
    \item Avoid registering the same type multiple times to prevent conflicts.
    \item Use \texttt{IInitializable} for post-injection setup logic.
\end{itemize}
