\section{Logging}
\label{sec:logging}

\texttt{MLGWorks.Utils.Logging.Logger} is a Unity singleton that mirrors application messages to the Unity console and writes configured log files. It queues entries, so Unity's threaded log callback can translate messages without performing file work on the callback thread.

\subsection{Setup}
Add a GameObject with the \texttt{Logger} component to a scene. Configure \texttt{pathType}, \texttt{relativePath} or \texttt{customPath}, \texttt{fileExtension}, \texttt{maxLogFileCount}, and whether debug messages should be enabled. File writers are initialized lazily on the first application message.

\begin{lstlisting}
using MLGWorks.Utils.Logging;

Logger.Info("Application started.");
Logger.Warning("A fallback value was used.");
Logger.Error("The save operation failed.");
\end{lstlisting}

The static methods are \texttt{Debug}, \texttt{Info}, \texttt{Warning}, and \texttt{Error}. \texttt{EmitTestLogs()} emits one message at each standard level, which is useful when checking a project setup.

\subsection{File routing}
\texttt{LogLevel} values are routed by bit masks. Bit 0 is the debug file, bit 1 the info file, bit 2 the warning file, bit 3 the error file, and bit 4 the combined file. For example, \texttt{(1 << 0) | (1 << 4)} sends debug entries to both debug and combined files.

\texttt{LogLocationType.PersistentDataPath} is the normal application location; \texttt{DataPath} uses the project data path, and \texttt{Custom} uses \texttt{customPath}. \texttt{CleanupOldLogFiles()} removes the oldest complete timestamped sessions until \texttt{maxLogFileCount} is satisfied. A negative maximum keeps all sessions.

\subsection{Lifecycle}
The logger flushes its queue during \texttt{Update()}, unsubscribes from Unity log callbacks, and closes writers during shutdown. In editor tests, \texttt{FlushAndShutdown()} is available to force the same cleanup path immediately. The editor integration is in \texttt{Logging/Editor}.
